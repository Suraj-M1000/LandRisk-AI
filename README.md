# LandRisk AI

**A Django-based project management and machine learning application for exploring early detection of potential infrastructure project delays.**

LandRisk AI is a portfolio project inspired by the problem of identifying land acquisition and schedule-related risks in infrastructure projects. It combines a Django web application with a machine learning inference pipeline to demonstrate project tracking, risk assessment, and model explainability.

> **Disclaimer:** This project uses synthetic data. Its predictions demonstrate a machine learning workflow and are not validated forecasts of real-world project delays. It is not intended for government decision-making or operational deployment.

## Features

- **User authentication:** Account registration and login.
- **Project management:** Create, view, update, and delete projects.
- **Project ownership:** Users can manage their own projects.
- **Dashboard:** Review project information through summary metrics and visualizations.
- **Risk prediction:** Generate risk assessments using a trained Logistic Regression model.
- **Prediction history:** Review previously generated predictions.
- **Model explanations:** Inspect contributing risk factors and suggested actions.
- **Input validation:** Validate project inputs and reject inconsistent values.
- **Automated tests:** Test application behavior, ownership restrictions, and ML inference.

## Machine Learning Workflow

The application uses a Logistic Regression classifier to demonstrate risk classification from project information.

The input features include:

- Project sector and state
- Project cost and planned duration
- Elapsed time and physical progress
- Expenditure percentage
- Contractor experience
- Land acquisition requirement and progress

The workflow includes synthetic data generation, exploratory data analysis, preprocessing, model evaluation, saved model artifacts, inference, and explanations.

The trained model and its metadata are stored in `ml/artifacts/`. The model card documents the input schema, threshold selection, evaluation metrics, library versions, and limitations.

### Reported evaluation

The current model card reports the following test-set results:

| Metric | Score |
|---|---:|
| ROC-AUC | 0.729 |
| Precision | 0.507 |
| Recall | 0.729 |
| F1-score | 0.598 |

These metrics describe performance on a synthetic test set, not real infrastructure projects. The test set was evaluated more than once during model development, and probability calibration has not been verified. Results should therefore be interpreted cautiously. The application should communicate risk bands rather than treating predicted probabilities as calibrated real-world probabilities.

## Synthetic Dataset

The project currently uses generated infrastructure project data rather than a verified, real-world row-level dataset of land acquisition delays.

The data generator uses a fixed random seed to support reproducibility.

- `ml/data/infrastructure_projects.csv` — synthetic project features and outcomes.
- `ml/data/hidden_truth.csv` — companion data generated by the data-generation workflow.
- `ml/generate_data.py` — synthetic data generator.
- `docs/DATA_CARD.md` — dataset documentation.
- `docs/PROBLEM_SPEC.md` — problem definition and project scope.

The generated dataset is intended for development, experimentation, and demonstration. It should not be interpreted as evidence about actual project delays.

## Getting Started

### Prerequisites

- Python 3.13.7, matching the current development environment
- Git
- PowerShell on Windows, or an equivalent terminal

### 1. Clone the repository

After the project is published on GitHub, replace the placeholder below with the actual repository URL:

```powershell
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd LandRisk-AI
```

Alternatively, open your existing local project directory.

### 2. Create and activate a virtual environment

On Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use an approved local execution-policy configuration or activate the environment through your IDE.

### 3. Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure environment variables

The project supports these environment variables:

- `DJANGO_SECRET_KEY`
- `DJANGO_DEBUG`
- `DJANGO_ALLOWED_HOSTS`

For local development, the settings provide a development-only fallback secret key. For deployment, set a strong, unique secret through the environment and configure the permitted hosts. Never commit production secrets.

### 5. Apply database migrations

```powershell
python manage.py migrate
```

### 6. Create an administrator account (optional)

```powershell
python manage.py createsuperuser
```

### 7. Run the development server

```powershell
python manage.py runserver
```

Open `http://127.0.0.1:8000/` in your browser.

## Running Tests

Run the Django test suite:

```powershell
python manage.py test
```

Run the standalone ML inference tests:

```powershell
python -m unittest Test.test_inference -v
```

Check the Django configuration:

```powershell
python manage.py check
```

## Security and Data Handling

- The local SQLite database is excluded from version control.
- Virtual environments and generated Python cache files are excluded.
- Production secret keys must be supplied through environment variables.
- User-specific project access is enforced by the application's ownership logic.
- The application is a development and portfolio project, not a production-hardened service.

## Current Limitations

- The model is trained on synthetic data.
- Real-world predictive performance has not been established.
- Probability calibration has not been verified.
- Evaluation metrics have limitations documented in the model card.
- The current application is intended for learning and demonstration.
